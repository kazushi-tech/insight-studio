# Discovery/LP Comparison レポート品質 向上計画

## Context

スポーツサプリメント市場（SAURUS）の競合分析レポートを生成したが、**広告運用プロフェッショナル目線では「分析・類推の質がまだ甘い」**と判定。具体的には以下の問題がある：

1. **競合セットが分断** — Discovery（WINZONE/Glico）と Compare（Myprotein/X-PLOSION）で別々のレポートが生成され、統合的な競合把握が不可能
2. **定量性が足りない** — 市場規模「年率5-8%（ソースなし）」、広告費推定なし、CPA/ROAS目標なし、検索ボリューム推定なし
3. **3社内の相対順位しかない** — 「1位/2位/3位」は市場全体では無意味。絶対評価スケールが必要
4. **「評価保留」だらけ** — SAURUSの価格が取得不可で、推奨施策の多くが「データ取得後に実行」＝未完了
5. **施策が汎用的** — 「指名防衛キャンペーン整備」「非指名獲得LP制作」は初心者でも言える内容。予算感・キーワード戦略・CPA目標がない
6. **消費者インサイトがない** — レビュー分析・購買決定要因・価格感度の推定が欠落
7. **KPI測定計画がない** — 「4-8週で評価」はあるが、具体的な目標値・測定方法がない

**良かった点** — 証拠トレーサビリティ（確認済み/推定/評価保留）、L1-L5信頼レイヤー、データ制約への正直さ、構造化フォーマット

## 改善計画（4フェーズ × 2レポ）

### Phase 1: フロントエンド品質可視化（insight-studio リポのみ）

> ユーザーがレポートの信頼性を一目で判断できるようにする

#### 1-1. データカバレッジスコアカード追加
- **新規ファイル**: `src/components/DataCoverageCard.jsx`
- **変更ファイル**: `src/pages/Discovery.jsx`, `src/pages/Compare.jsx`
- **内容**: 各サイトの抽出成功率をミニバーチャートで表示。「平均取得率 7.2/10 — 高信頼」vs「4.1/10 — 注意：一部評価が不完全データに基づく」
- **欠損フィールド強調**: 特に `pricing_snippet`, `main_cta` が欠けている場合に警告表示

#### 1-2. MarkdownRenderer 条件付きスタイル強化
- **変更ファイル**: `src/components/MarkdownRenderer.jsx`
- **内容**:
  - `確認済み` → 緑バッジ、`推定` → 琥珀バッジ、`評価保留` → 灰バッジ
  - `1位/2位/3位` → 順位に応じた色分け
  - `取得不可` → 斜体グレーで視覚的に目立たなくする
  - `【市場推定】` → 青小バッジ（AI推測 vs 抽出ファクトの区別を明確化）

#### 1-3. reportQuality.js 拡張
- **変更ファイル**: `src/utils/reportQuality.js`
- **新規チェック**:
  1. **定量クレーム検証**: `¥[\d,]+` をスキャンし、該当サイトのpricingが「取得不可」なら警告
  2. **市場規模ソースチェック**: 「年率X%」が【市場推定】なしで登場したら警告
  3. **評価保留密度チェック**: 評価軸の40%超が「評価保留」なら「データ不足により結論の信頼性が制限」警告
  4. **競合セット重複チェック**: 同一ブランドでDiscovery/Compare両方ある場合、矛盾する評価を検出

#### 1-4. レポート間クロスリンク
- **変更ファイル**: `src/pages/Discovery.jsx`, `src/pages/Compare.jsx`
- **内容**: 同一ブランドで両方のレポートが存在する場合、レポート末尾に「関連レポート」カードを表示（どの競合が使われたかを明示）

### Phase 2: バックエンドプロンプト改善（market-lens-ai リポ）

> レポートの「中身」を根本的に改善する最も重要なフェーズ

#### 2-1. 定量市場コンテキスト層の強化
- **変更ファイル**: `web/app/analyzer.py` — `_MARKET_CONTEXT_LAYER` 定数
- **現状**: 「成長市場」等の方向性のみ。数字なし。
- **改善**: 数値を許可するが、全てに「推定」と「信頼度」を強制
  ```
  ### 市場概況（AI推定・参考値）
  | 項目 | 推定値 | 信頼度 | 根拠 |
  | 日本市場規模 | ¥XXX億（推定） | 低〜中 | 業界動向からの推定 |
  | 成長率 | 年率X-Y%（推定） | 低〜中 | 公開データからの類推 |
  ```

#### 2-2. 競合広告投資推定フレームワーク追加
- **変更ファイル**: `web/app/analyzer.py` — 新規定数 `_COMPETITIVE_INTELLIGENCE_LAYER`
- **内容**: 各ブランドの推定月間広告費レンジ・主戦場・推定手法をAI推定（信頼度付き）で生成
  ```
  | ブランド | 推定月間広告費レンジ | 主戦場 | 推定手法 | 信頼度 |
  ```
  - 常にレンジ（点推定なし）
  - 「AI推定」ラベル必須
  - LP複雑性・可視マーケティング活動・業界水準を根拠として明示

#### 2-3. 予算フレームワーク追加
- **変更ファイル**: `web/app/analyzer.py` — `_AD_OPERATIONS_LAYER`, `_ENHANCED_ACTION_PLAN_TEMPLATE`
- **現状**: Phase設計はあるが¥金額なし
- **改善**: セクション5に「予算フレーム」を追加
  ```
  #### 5-0. 予算フレーム（AI推定・参考値）
  | 項目 | 初期月額予算レンジ | 根拠 | 条件 |
  | 指名防衛 | ¥XX万〜¥XX万 | 推定検索ボリューム基準 | 実測後に調整 |
  ```

#### 2-4. 評価スケールの変更（微小サンプル順位 → 強度分類）
- **変更ファイル**: `web/app/analyzer.py` — `_COMPETITIVE_TIER_INSTRUCTIONS`
- **現状**: 「相対順位（1位/2位/3位）」
- **改善**: 新スケールに変更
  - `強` — 明らかに強い、明確な証拠あり
  - `同等` — 他と遜色なし
  - `弱` — 明らかに弱い
  - `—（評価保留）` — 判断不可
  - 必須文言: 「今回比較したNサイト内での相対評価であり、市場全体の順位を示すものではありません」

#### 2-5. データカバレッジに応じた結論制限
- **変更ファイル**: `web/app/analyzer.py` — `_EVIDENCE_RIGOR_RULES`
- **新ルール**:
  - 平均取得率 ≥7/10 → 全セクション通常評価可
  - 5-6/10 → 「データ制約あり」注記、定量推定はレンジ幅広く
  - <5/10 → 定性的方向性のみ、数値推定禁止
  - 全ブランドで特定フィールドが一律取得不可 → 「同条件比較不可」と明記

## Agent Team 構成（実行時）

実行フェーズでは `/agent-team-workflow` スキルを使って並列実行：

```
Team Alpha（insight-studio リポ）:
  ├─ Agent A: DataCoverageCard + reportQuality.js 拡張
  └─ Agent B: MarkdownRenderer 条件スタイル + クロスリンク

Team Beta（market-lens-ai リポ）:
  ├─ Agent C: プロンプト改善（市場コンテキスト + 評価スケール + 予算フレーム）
  └─ Agent D: プロンプト改善（競合インテリ + 消費者インサイト + KPI）
```

各Wave完了後に `/codex-review` スキルで品質ゲートを実施。

## 検証方法

1. **ベースライン取得**: 変更前に `saurusjapan.com` で Discovery + Compare を実行し、結果を保存
2. **品質ゲート通過率**: `reportQuality.js` の警告発生率を追跡（Wave毎に30%減を目標）
3. **評価保留出現率**: 改善前後で「評価保留」の出現率を比較
4. **プロフェッショナルレビュー**: 各Wave後に以下を評価
   - 「そのままクライアントに提出できるか？」
   - 「具体的に何が足りないか？」
   - 「誤解を招く情報はないか？」
5. **テスト**: バックエンドテスト397テストが全通過することを確認

## 変更しないこと

- **外部データソースの追加なし** — Google Ads API / Keyword Planner は呼べない。定量推定は全てAI推定 + 信頼度ラベル
- **DB統合なし** — ファイルベースのまま。`consistency_cache/` を既存メカニズムとして使用
- **Token予算の増加なし** — `_MULTI_URL_MAX_OUTPUT_TOKENS = 8192` を維持。内容を密にする（長くしない）
- **リポジトリ分割の変更なし** — insight-studio（フロント）と market-lens-ai（バック）の構成は維持

# プロジェクト管理 & RBAC 導入計画

## Context
現在のInsight Studioは単一パスワード認証で全案件が見える状態。クライアントに見せる際に他案件のデータが露出するリスクがある。Juicerのようなサイト管理UIを参考に、**管理者は全案件を管理、クライアントは自分の案件のみアクセス**できるRBACを導入する。

---

## ステップ①: Stitch 2.0 プロンプト（メイン成果物）

以下をStitch 2.0に貼り付けてUI生成する。

```
# Insight Studio — プロジェクト管理ダッシュボード

## Context
Insight Studioは広告運用分析SaaS（PC専用）。このページは管理者がクライアントプロジェクトを一元管理する**プロジェクト管理**画面。各プロジェクトはクライアントのBigQueryデータセットに紐づく。

## デザインシステム（厳守）
- **フォント:** Manrope（見出し/ラベル）、Inter（本文）
- **カラーパレット:**
  - Primary: #0f5238（深緑）、Primary Container: #2d6a4f
  - Surface/Background: #f8f8f5（暖かみのあるオフホワイト）
  - Card: #ffffff、Surface-container-low: #f4f4ef
  - テキスト: #1a1c19、サブテキスト: #404943
  - ゴーストボーダー: #bfc9c1 at 15% opacity
  - Error: #ba1a1a、Success: #2e7d32
  - サイドバー: #14291e（ダークフォレストグリーン）
- **レイアウトルール:**
  - 区切り線は使わない — トーナルな背景色の変化で区切る
  - カード: border-radius 12px、白背景
  - ボタン: border-radius 12px、プライマリは#2d6a4f背景+白文字
  - ホバー: box-shadow 0 12px 32px -12px rgba(26,28,25,0.08)
  - 余白: ページ2.5rem、カード内1.5rem
  - ゴーストボーダーのみ: outline-variant 15%
- **アイコン:** Material Symbols Outlined（filledではない）
- **言語:** 日本語UIラベル

## ページ構成

### 左サイドバー（既存 — コンテキストとして表示）
ダークグリーン(#14291e)サイドバー。Insight Studioロゴ、ナビ項目あり。「プロジェクト管理」がアクティブ状態（#2d6a4fでハイライト）。

### トップヘッダー
- 左: プロジェクト切替ドロップダウン（フォルダアイコン+現在のプロジェクト名）
- 右: APIキーボタン、ガイドボタン、テーマ切替、ユーザーアバター+名前

### メインコンテンツ — プロジェクト一覧

#### ヘッダー行
- 左側:
  - ページタイトル: 「プロジェクト管理」（Manrope, bold, #1a1c19）
  - サブタイトル: 「クライアントプロジェクトの管理・BigQuery接続・アクセス権限設定」（#404943, Inter, 0.875rem）
  - 登録件数バッジ: 「8件登録」（ピル型、#eeeee9背景、#404943文字）
- 右側:
  - 検索入力欄（虫眼鏡アイコン、surface-container-low背景、rounded-xl）
  - 「新規プロジェクト」ボタン（プライマリ、#2d6a4f背景、白文字、"add"アイコン）

#### 統計カード（テーブル上部）
横並び4枚のメトリクスカード:
1. 「全プロジェクト」— 件数 + folderアイコン
2. 「アクティブ」— 件数 + 緑ドット
3. 「BQ接続済」— 件数 + databaseアイコン
4. 「クライアント数」— 件数 + peopleアイコン
各カード: 白背景、12px radius、アイコン+数値+ラベル、ゴーストボーダー

#### プロジェクトテーブル
白カード(#ffffff)コンテナ、12px radius、ボーダーなし（ゴーストボーダー15%のみ）。

テーブル列:
1. **プロジェクト名** — 太字プロジェクト名(Manrope) + クライアント企業名（小さいグレー文字） + dataset ID（等幅フォント、さらに小さく）
2. **クライアント** — クライアント名 + 小さいアバターサークル（イニシャル）
3. **BQ接続** — ステータスバッジ: 緑ドット+「接続OK (Xテーブル)」or 赤ドット+「未接続」
4. **データ量** — 月間データ量「1.2M行/月」
5. **ステータス** — ピルバッジ: 緑「アクティブ」or グレー「停止中」
6. **最終更新** — 日本語日付フォーマット
7. **操作** — アイコンボタン行:
   - "visibility"アイコン（ダッシュボード表示）— #2d6a4f
   - "edit"アイコン — #404943
   - "share"アイコン（クライアントにアクセス共有）— #456553
   - "delete"アイコン — #ba1a1a（ホバー時のみ表示）

テーブル行:
- ホバー: #f4f4efに変化
- 選択中のプロジェクト: 左端に#2d6a4fの3pxアクセントボーダー
- 5〜6行のサンプルデータ（リアルな日本企業名で）

### モーダル: プロジェクト作成/編集（オーバーレイ）
中央配置、幅560px、白背景、12px radius、バックドロップぼかし:
- タイトル: 「新規プロジェクト作成」
- フォーム（surface-container-low背景のinput、rounded-xl）:
  - プロジェクトID（テキスト、等幅プレースホルダー "例: client_abc"）
  - プロジェクト名（テキスト）
  - クライアント名（テキスト）
  - クライアントメール（email、招待用）
  - BigQuery Dataset ID（テキスト、等幅、任意）
  - 説明（textarea、任意）
- フッター: 「キャンセル」テキストボタン + 「作成」プライマリボタン

### モーダル: アクセス共有 / クライアント招待
別のモーダル:
- タイトル: 「アクセス共有」
- プロジェクト名を表示
- メール入力 + 権限セレクタ（ドロップダウン: 「閲覧のみ」/「編集可」）
- 「招待を送信」プライマリボタン
- 現在のアクセス一覧: アバター + 名前 + メール + 権限バッジ + 削除ボタン

## デザインノート
- プレミアムなエディトリアルデータダッシュボードの雰囲気 — 落ち着き、余白、フォレストグリーンのトーン
- ステータス表示以外は派手な色を使わない
- セクション間にたっぷりの余白
- テーブルテキストは小さめ(0.875rem/0.75rem)だが行間を広く
- Material Symbolsアイコンを全面的に使用（outlinedウェイト）
- 既存Insight Studioアプリの自然な延長として見えること
```

## ステップ③: 実装 & テスト

### RBACロール定義

| ロール | 案件一覧 | 作成/編集 | BQ接続 | 招待 | 分析機能 |
|--------|---------|----------|--------|------|---------|
| admin | 全件 | ○ | ○ | ○ | 全案件 |
| client | 自分のみ | × | × | × | 自分のみ |

### バックエンド変更（ads-insights側）

- `users` テーブル: user_id, email, password_hash, display_name, role
- `project_members` テーブル: project_id, user_id, permission
- JWTにrole含む
- `GET /api/ads/cases` をロールでフィルタ

### フロントエンド変更

| ファイル | 変更 |
|---------|------|
| `src/contexts/AuthContext.jsx` | userオブジェクト、loginV2(email,pw)、role |
| `src/pages/ProjectManagement.jsx` | 新規: Stitch出力を実装化 |
| `src/contexts/RbacContext.jsx` | 新規: 権限判定フック |
| `src/App.jsx` | /loginルート、AdminGuard |
| `src/components/Layout.jsx` | ロールでナビ出し分け |
| `src/api/adsInsights.js` | 新API関数 |

### 移行戦略
既存 `CaseManagement.jsx` は残す。`ProjectManagement.jsx` がRBAC対応版として並存し、バックエンド準備後に切替。

### 検証手順
1. 管理者ログイン → 全プロジェクト一覧表示
2. プロジェクト作成 → クライアント招待
3. クライアントログイン → 自分の案件のみ表示
4. クライアントがダッシュボード/分析にアクセスOK
5. 他案件アクセス → 403確認

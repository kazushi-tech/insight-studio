# SAURUS 競合分析レポート品質改善プラン

## Context

2つのAI生成レポート（Market Lens LP Compare / Discovery Hub）を広告運用プロフェッショナルの視点で精査した結果、**分析精度・類推品質ともに実務レベルには未到達**と判定。プロンプト設計・データ抽出・出力構造の3層にまたがる構造的問題を特定し、改善プランを策定する。

---

## 総合評価: レポート品質判定

### 結論: 実務投入には不十分 — 改善余地が大きい

| 評価軸 | 現状 | 目標 | ギャップ |
|--------|------|------|---------|
| データ網羅性 | **D** — 全ブランド価格取得不可、FAQ/レビュー欠損多発 | B+ | 大 |
| 分析の深さ | **C** — サイト種別分類で止まり。ポジショニング分析・市場文脈なし | A- | 大 |
| 類推の妥当性 | **B-** — 証拠ラベル（確認済み/推定）は適切。ただし「推定」の根拠が薄い | A- | 中 |
| 施策の実行可能性 | **C+** — テンプレ通りの施策。具体コピー・予算感・ROI観点なし | A- | 大 |
| レポート間整合性 | **D** — 同一ブランドの評価が2レポートで矛盾 | B+ | 大 |

### 良い点（認めるべき成果）

1. **証拠強度ラベル（確認済み/推定/評価保留）の使い分け**は正確。L1-L5信頼階層も適切に運用
2. **参考観測枠の分離**（グリコを主比較から除外）は正しい判断
3. **施策の「確認→制作→配信」順序**は広告運用の実務フローに即している
4. **除外クエリの提案**（`SAURUS 解約`、`プロテイン レシピ` 等）は的確
5. **事実と推定の文レベル分離**が概ね守られている

### 根本的問題5つ

---

## 問題1: 全ブランド価格データ0% — 比較分析の土台崩壊

**現象**: SAURUS / VITAS / グリコ / MPN / UP ATHLETE — 5ブランド中5ブランドで `pricing_snippet = 取得不可`

**影響**:
- 価格競争力の評価が不可能（評価保留の嵐）
- 「価格・オファー」軸が全ブランドで「—（評価保留）」→ 競合比較の核心が欠落
- 施策の最優先が「shopドメイン情報取得」=「データが足りない」告白で終わる

**根本原因** (`extractor.py` lines 242-272):
- `_extract_pricing()` がCSS selectors + regex fallback のみ
- JSON-LD Product/Offer schema を読んでいない
- JavaScript描画の価格を取得できない
- `data-price`属性、`<meta property="product:price:amount">` を見ていない

---

## 問題2: 「指名向き vs 非指名獲得向き」分類がトートロジー

**現象**: ブランドサイト→「指名流入向き」、EC→「非指名獲得向き」。これはAIでなくてもわかる

**影響**:
- 分析が表面的。「なぜ」「どう差別化すべきか」がない
- クライアントへの戦略提案として価値ゼロ
- 全ブランドが「中」に収束する曖昧な3段階評価

**根本原因** (`analyzer.py` lines 677-682):
- 獲得タイプ判定が「サイト種別」と紐づき（ブランドサイト=指名向き、EC=非指名獲得向き）
- ポジショニングマップ、差別化軸、ターゲットセグメント別の勝ち筋分析がプロンプトに不在
- 市場コンテキスト（市場規模、検索ボリューム、競合環境）をAIに使わせる指示がない

---

## 問題3: トークン予算不足でSection 5が形骸化

**現象**: 3サイト比較で output token 6,144 — 日本語約4,500字。15種類の制約テンプレートを満たしつつ5セクション+3レイヤー施策を書くには不足

**影響**:
- Section 4（ブランド別評価）で予算を消費し、Section 5（実行プラン）が浅い
- LP改善施策が「FVにshopへの導線追加」止まり。具体的なコピー・レイアウト・優先順位なし
- 検索広告施策がテンプレ填め

**根本原因** (`analyzer.py` lines 23-26):
```python
_MULTI_URL_MAX_OUTPUT_TOKENS_3_SITES = 6144  # ← 足りない
```
入力プロンプトが約30,000文字（制約テンプレート15種）で、出力は6,144トークン。入力:出力比率が不健全。

---

## 問題4: 制約テンプレート過多でモデルが「安全側」に逃げる

**現象**: 15種類の「禁止」「厳守」テンプレートが約15,000文字。分析指示は約5,000文字。3:1で制約が勝つ

**影響**:
- モデルが「間違えない」ことを最優先し、「鋭い洞察」を犠牲に
- 全項目が「中」に収束（断定禁止ルールの過剰遵守）
- スポーツサプリテンプレートが2重挿入されている（lines 1066 + 1178）

---

## 問題5: レポート間のSAURUS評価が矛盾

**現象**:
- Report 1: SAURUS 信頼訴求強度 = **中**
- Report 2: SAURUS 信頼訴求強度 = **高**

**影響**: クライアントに2レポート提出時に「どっちが正しいのか」と突っ込まれる

**根本原因**: 品質ゲート（`report_generator.py`）にブランド横断の一貫性チェックが存在しない

---

## 改善プラン: 4フェーズ

### Phase 1: 即時改善（analyzer.py のプロンプト修正のみ）

**変更対象**: `tmp_market_lens_ai_repo/web/app/analyzer.py`

#### 1-1. トークン予算を2倍に拡大

```python
# 現状
_MULTI_URL_MAX_OUTPUT_TOKENS_3_SITES = 6144
# 改善後
_MULTI_URL_MAX_OUTPUT_TOKENS_3_SITES = 12288
```

同様に2サイト(4096→8192)、4+サイト(5120→10240)も拡大。Claude Sonnet 4.6 の max_tokens 上限内。

#### 1-2. 重複テンプレート除去

`build_deep_comparison_prompt()` 内で `_SPORTS_SUPPLEMENT_TEMPLATE` が2回挿入されている（lines 1066 と 1178）。1箇所に統合。

#### 1-3. 制約テンプレートを system メッセージに分離

`anthropic_client.py` の `call_text_model()` に `system` パラメータを追加。
安定的な制約ルール（証拠階層、推論抑制、信頼分類）を system message に移動し、user message は分析指示に集中させる。

**期待効果**: レポート完結率向上、Section 5 の具体性改善、「中」収束の軽減

#### 1-4. 評価スケールを「絶対評価3段階」から「相対ランキング」に変更

現状のプロンプト指示:
```
獲得対応力 / 信頼訴求強度 / 購買導線整備度 は `高 / 中 / 低` の3段階で評価
```

改善後:
```
獲得対応力 / 信頼訴求強度 / 購買導線整備度 は
今回比較対象内での相対順位（1位/2位/3位）で評価し、
順位の根拠となる「差別化要因」を1文で明記すること。
全ブランドを同順位にすることは禁止。
```

---

### Phase 2: 分析フレームワーク強化（1-2週間）

**変更対象**: `analyzer.py` にテンプレート追加

#### 2-1. 競合ポジショニングフレームワーク追加

新テンプレート `_COMPETITIVE_POSITIONING_FRAMEWORK` を追加:

```
## 競合ポジショニング分析（必須・Section 3の前に挿入）

### 2軸ポジショニングマップ
- X軸: 価格帯（低〜高）— 取得データまたは業界知識から推定
- Y軸: ターゲット層の本格度（一般フィットネス〜競技アスリート）

`| ブランド | 推定価格帯 | ターゲット本格度 | ポジション要約 | 空白セグメント |`

### 差別化要因の3分類
各ブランドについて:
- 機能的差別化: 成分、配合、認証（具体的に何が違うか）
- 情緒的差別化: ブランドストーリー、アスリート支持（なぜ選ばれるか）
- 経済的差別化: 価格、定期便、送料（どう買いやすいか）
```

#### 2-2. 市場コンテキスト層の追加

新テンプレート `_MARKET_CONTEXT_LAYER`:

```
## 業界コンテキスト（必須・エグゼクティブサマリー内）

AIの知識を使い以下を【市場推定】ラベル付きで追加:
1. 日本のスポーツプロテイン市場の概況（成長トレンド）
2. 主要検索キーワードの相対的ボリューム（高/中/低）
3. 一般的な価格レンジ（カテゴリ相場観）
4. オンライン購買の主要チャネル（自社EC / Amazon / 楽天）
```

#### 2-3. 施策テンプレートにモックアップレベルの具体性を要求

Section 5 の出力指示を強化:

```
#### 5-0. データ取得課題（施策ではなく前提の制約）
`| 不足データ | 取得元 | 難易度 | 取得後インパクト |`
※戦略アクションとは分離して記載

#### 5-1. LP改善施策（モックアップレベル）
`| # | ブランド | 優先度 | 改善箇所 | 現状の状態 | 改善後の具体案（コピー/配置/CTA文言） | 推奨着地先 | 工数 | 根拠 | 証拠強度 | ファネル | 期待効果 |`
```

### Phase 3: データ抽出パイプライン改善（2-3週間）

**変更対象**: `extractor.py`, `models.py`, `fetcher.py`

#### 3-1. 価格抽出の強化 (`extractor.py`)

`_extract_pricing()` に以下のフォールバックを追加:
1. JSON-LD `Product` / `Offer` schema から `price`, `priceCurrency` を抽出
2. `<meta property="product:price:amount">` 抽出
3. `data-price`, `data-amount` 属性スキャン
4. 日本EC特有セレクター: `.product__price`, `.price-box`, `.ec-price`, `[class*='kakaku']`

#### 3-2. サブドメイン商取引リンク発見 (`extractor.py`)

新関数 `_extract_commerce_links(soup, base_url)`:
- `<a>` href を走査し `shop.`, `store.`, `ec.`, `cart.` サブドメインを検出
- Shopify / BASE / STORES / makeshop のパターンを検出
- 結果を `ExtractedData.commerce_links` フィールドに格納

→ pricing が空で commerce_links がある場合、scan_service でサブドメインを追加フェッチ

#### 3-3. FAQ / テスティモニアル抽出の強化 (`extractor.py`)

- `<details><summary>` パターン追加
- `[class*='accordion']` パターン追加
- `[class*='rating']`, `[class*='star']`, `[class*='kuchikomi']` セレクター追加
- Instagram oEmbed 検出（ソーシャルプルーフ）

---

### Phase 4: レポート間一貫性・品質ゲート強化（3-4週間）

**変更対象**: `report_generator.py`, 新規 `consistency_checker.py`

#### 4-1. ブランド評価キャッシュ

`consistency_checker.py` を新設:
- (brand_domain, evaluation_axis) をキーに直近評価をキャッシュ
- 新レポート生成時、同一ブランドの過去評価をプロンプトに注入
- 評価が変わる場合は理由の明示を強制

#### 4-2. 品質ゲートに整合性チェック追加

`report_generator.py` に:
- 同一ブランドの評価が過去レポートと乖離した場合 warning を挿入
- 競合セット選定の根拠が明記されていない場合 warning を挿入

#### 4-3. 制約テンプレート統合（15→8セクション）

| 統合前 | 統合後 |
|--------|--------|
| `_INFERENCE_SUPPRESSION_RULES` + `_EVIDENCE_SEPARATION_RULES` | `_EVIDENCE_RIGOR_RULES`（1つに統合） |
| `_TRUST_ELEMENT_TAXONOMY` + 断定抑制ルール inline | `_TRUST_AND_ASSERTION_RULES`（1つに統合） |
| `_PRICING_UNKNOWN_RULES` + `_EFFECT_RANGE_TEMPLATE` | `_DATA_LIMITATION_RULES`（1つに統合） |
| `_SPORTS_SUPPLEMENT_TEMPLATE` ×2 | ×1 に修正 |

## 検証方法

### Phase 1 検証
1. 同一URL（saurusjapan.com + 競合2社）で改善前後のレポートを比較
2. チェック項目:
   - Section 5 が途中切れしないこと（トークン予算増）
   - 評価テーブルが「中」一色にならないこと（相対ランキング）
   - スポーツサプリテンプレートが1回のみ出力（重複除去）

### Phase 2 検証
1. レポートにポジショニングマップが含まれること
2. エグゼクティブサマリーに市場コンテキスト（【市場推定】ラベル付き）が存在すること
3. LP改善施策に具体的なコピー文言・配置指示があること

### Phase 3 検証
1. shop.saurusjapan.com の価格が取得できること
2. bodyfit-mpn.com の価格（¥6,966）が正しく抽出されること
3. upathlete.jp の価格（¥3,480）が正しく抽出されること

### Phase 4 検証
1. 同一ブランドを異なる競合セットで分析した際、評価の矛盾に warning が出ること
2. 制約テンプレート統合後もL5制約、証拠分離ルールが機能すること

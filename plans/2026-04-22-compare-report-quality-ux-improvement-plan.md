# LP比較・競合分析レポート 品質・UX改善プラン

**作成日**: 2026-04-22  
**対象**: Market Lens AI — LP比較・競合分析（`/compare` ページ）  
**目標**: ① レポート品質B+ → A、② 処理時間8分 → 5分以内、③ UX課題4点解消

---

## 問題整理

### P0（即時対応）

| # | 問題 | 影響 |
|---|------|------|
| P0-1 | TOCが静的テキスト（アンカーリンクなし） | 長大レポートで目的セクションに辿り着けない |
| P0-2 | 処理時間 8分3秒 → 5分超過 | UX的に離脱リスク大 |

### P1（品質向上）

| # | 問題 | 影響 |
|---|------|------|
| P1-1 | 市場データが全項目 `low` 信頼度なのに表として提示 | ノイズ感・信頼性低下 |
| P1-2 | 予算レンジが60倍幅（40万〜2,400万円）で意思決定に使えない | レポートの実用性低下 |
| P1-3 | hero_copy取得失敗時に複数セクションが「評価保留」 | 競合分析の完成度が下がる |

### P2（UX改善）

| # | 問題 | 影響 |
|---|------|------|
| P2-1 | セクション折り畳みなし | 読了済み内容を閉じられず疲労感 |
| P2-2 | TRACKINGセクション（最下部）が情報薄 | 目的が不明確 |

## 改善計画

---

### [P0-1] TOCをアンカーリンク付きスティッキーサイドバーに変更

**変更対象**: `src/` フロントエンド — CompareReport コンポーネント

**現状**: 目次が `<div>` の静的テキストとして埋め込まれており、クリックしても遷移しない

**対応内容**:

1. **レポート各セクションに `id` を付与**
   - `executive-summary`, `analysis-target`, `competitive-summary`, `brand-evaluation`, `action-plan`, `notes`, `appendix` など

2. **目次コンポーネントをフローティングサイドバー化**
   ```
   位置: レポートの左側 or 右側に固定（position: sticky, top: 80px）
   表示条件: レポート表示時のみ（URLがcompareかつreportが存在する場合）
   折り畳み: デフォルト展開、クリックで最小化（「≡」ボタン）
   アクティブハイライト: スクロール位置に追従してTOCの現在位置をハイライト
   ```

3. **スクロール動作**: `scrollIntoView({ behavior: 'smooth' })` でアニメーション付き遷移

**Stitch2プロンプト**:
```
LP比較・競合分析レポートページに、スティッキーなサイドナビゲーション（目次）を追加してください。

レポートエリアの左側（幅200px）に固定配置し、ページスクロールに追従するようにします。
目次の各項目はクリックすると対応セクションへスムーススクロールします。
現在表示中のセクションをアクティブ状態（左ボーダーをBotanical Greenに、テキストを太字に）でハイライトします。
目次は折り畳みボタン（「≡」アイコン）で最小化でき、最小化時は右端にタブとして残ります。
デザインはサイドバーの背景を warm off-white (#fafaf5)、ボーダーなし、font-size 13px、Manropeフォントで。
レポートが存在しない（未分析）状態では表示しません。
```

### [P0-2] 処理時間5分以内に短縮

**現状推定ボトルネック**: バックエンド `backends/market-lens-ai/`

**調査・対応手順**:

1. **バックエンドのタイムライン計測ログを追加**
   - クロール開始/完了、LLM呼び出し開始/完了の各タイムスタンプをログ出力
   - 3サイト分が直列実行か並列実行かを確認

2. **クロール並列化**（直列の場合）
   - 3サイトのクロールを `asyncio.gather()` で並列実行
   - 期待削減: クロール時間を 1/3 に

3. **プロンプト最適化**
   - 市場推定ブロック（Section 3-1、3-2）はLLM呼び出しではなく、`market_estimator` からの直接マッピングに変更
   - これにより1回分のLLM呼び出しを削減

4. **モデル設定確認**
   - 現在のモデルがSonnet + MAX_COMPETITORS=3 であることを確認（PR #70で設定済み）
   - Haikusへのダウングレードは品質劣化リスクあり、実施しない

**目標タイムライン**:
```
クロール（3サイト並列）: 約60秒 → 現状推定120秒から短縮
LLM分析（並列化可能な部分）: 約120秒
レポート生成: 約60秒
合計目標: 240〜300秒（4〜5分）
```

### [P1-1] 市場データ表の表示ロジック改善

**問題**: 6項目全て `low` 信頼度の表がレポートの重要セクションを占めており、信頼性を損なう

**対応**: 全項目が `low` の場合、詳細テーブルを折り畳みにして代わりに注記のみ表示

```
【表示ロジック】
- 全項目 low → 「市場データは業界一般値のため、実際の運用データ取得後に更新してください」という注記カードのみ表示、テーブルは「詳細を表示（参考値）」で折り畳み
- 一部 medium/high → 通常テーブル表示
```

---

### [P1-2] 予算レンジの絞り込み

**問題**: 40万〜2,400万円/月という60倍幅は意思決定に不向き

**対応**: プロンプト改善 — 推定レンジを「初期フェーズ推奨値」として3段階に絞り込む

```
現状: 40〜2,400万円/月（1ブランドあたり・推定レンジ）
改善後:
  スモールスタート: 40〜150万円/月（月10〜40件CV想定）
  標準: 150〜500万円/月（月40〜150件CV想定）
  アグレッシブ: 500〜2,400万円/月（月150件以上CV想定）
```

ユーザーがどのフェーズを想定しているか入力できるオプションも長期的には追加検討。

---

### [P1-3] hero_copy取得失敗時のフォールバック戦略

**問題**: ALUHAのhero_copyが取得不可 → FV訴求・検索意図一致が「評価保留」になりレポート完成度低下

**対応**:

1. **Playwright/Puppeteerによる動的レンダリングクロールをフォールバックとして追加**
   - 通常のHTML取得が失敗した場合、自動でJS renderingクロールを試みる
   - ただし処理時間増加に注意 → タイムアウト15秒以内

2. **評価保留セクションの視覚的分離**
   - 評価保留のブランドには「⚠ 一部データ未取得」バナーを表示
   - 評価保留の項目はグレーアウトし「調査が必要です」リンクを添付

### [P2-1] セクション折り畳み機能

**対応**: 各主要セクション（エグゼクティブサマリー、ブランド別評価、実行プランの各サブセクション等）にアコーディオン展開/折り畳み機能を追加

**Stitch2プロンプト**:
```
LP比較・競合分析レポートの各セクション（エグゼクティブサマリー、分析対象と比較前提、競合比較サマリー、ブランド別評価、実行プラン、注記・前提条件）に折り畳み機能を追加してください。

各セクションのヘッダー行右端に「∧ / ∨」シェブロンアイコンを配置し、クリックで本文をスムーズにアニメーション（0.2秒）で展開/折り畳みできるようにします。
デフォルト状態は全セクション展開。
折り畳み状態はページ内のみ保持（リロードでリセット）。
```

---

### [P2-2] TRACKINGセクション改善

**問題**: 最下部のTRACKINGセクションにブランドカードが並んでいるが、何を追跡しているのかが不明確

**対応**:
- セクションの目的を明確化: 「このレポートの施策を実施した際のKPI追跡ダッシュボードへのリンク」
- 現状の「ブランド名カード」から「施策→KPI→測定ツール」の対応を示すテーブルに変更
- または、TRACKINGセクションを削除してKPIフレーム（Section 5-4）に統合

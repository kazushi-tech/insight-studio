# Plan: スポーツサプリ比較レポート品質の最終仕上げ

**作成日**: 2026-04-11  
**対象出力**:
- `LP比較・競合分析レポート`（SAURUS / WINZONE / Glico）
- `Discovery Hub レポート`（SAURUS / アミノバイタル / HALEO / SAVAS）

---

## Context

今回の新しい出力は、前回より明確に改善している。

改善した点:

1. `入力ブランド / 実分析対象 / 参考観測枠` の整理が前進した
2. `確認済み / 推定 / 評価保留` のラベル運用が前回より整った
3. `価格・定期便・送料・レビュー` のようなEC観点がHALEO / WINZONEで反映された
4. 広告アクションが、単なるLP診断ではなく運用示唆に近づいた

ただし、**広告運用の高水準レポート**としてはまだ未完成。

今回の最大の問題は、`品質チェックが効いている` のではなく、**品質異常を検知してもそのまま壊れたレポートを返している**こと。

これは「精度の不足」だけではなく、**提出物の品質管理として未完了**である。

### 判定

- **分析の質**: 実務二稿〜三稿の中間
- **類推の水準**: 前回より改善。ただし高水準とはまだ言えない

1. **比較の土俵整理は改善した**
   - Glico を `参考観測枠` に退避

   は、前回の不整合よりかなり良い。

2. **EC系競合の勝ち筋は読みやすくなった**
   - WINZONE: 認証 × 製薬会社品質 × 定期便

   - `4-8週で評価`
   - `効果レンジ`
   の表現は、以前の雑な数値断定より健全。

## まだ高水準ではない理由

### 1. 品質エラーを検知しても出力を止めていない

LP比較レポートでは、本文内にそのまま:

- `日付矛盾`
- `末尾欠け`
- `構造エラー`

が露出している。

これは「品質チェックが入った」こと自体は良いが、**クライアント提出物としては失格**。

正しい挙動は:

- 壊れたレポートを出さない
- 自動で再生成する
- 再生成できないなら `品質基準未達で再試行` として返す

のいずれか。

`壊れていますが参考までにどうぞ` は、提出品質として最もまずい。

### 2. 日付の owner がまだ統一されていない

今回も同一レポート内で:

- `実行日時`: 2026-04-11 04:40:06 UTC
- `作成日`: 2026年4月11日
- `分析実施日`: 2025年

が共存している。

これはモデルが本文内で日付を再生成しており、**レンダラ側の実行メタデータと衝突している**ことを示す。

高水準化するなら、日付は:

- generator / runtime metadata が唯一の owner

であるべき。

### 3. トークン上限に当たり、実務上必要な最後のアクションが切れている

今回も:

- LP比較レポートのアクション表が途中で切れる
- Discovery レポートも `#8` で途中切れ

になっている。

しかも LP比較の実行メタデータでは:

- `Completion Tokens: 6144`

で上限に当たっている。

つまり、これは偶発的な不具合ではなく、**出力設計上の恒常的な容量超過**。

### 4. キーワード意図分類が広告運用としてまだ甘い

Discovery のアクションで:

- `指名防衛: SAURUS プロテイン`
- `指名防衛: ランナー プロテイン`

が同じ箱に入っている。

しかし:

- `SAURUS プロテイン` は指名寄り
- `ランナー プロテイン` は非指名カテゴリ

であり、入札戦略もKPIも別。

これは広告運用の基本分類として重要。

### 5. 信頼要素の taxonomy がまだ粗い

今回の出力では、SAURUSの

- `ANTI DOPING`
- アシックス共催実績

を信頼要素として使っているが、
`ANTI DOPING` は現状の抽出では **ナビゲーション文字列の確認** に留まる。

それを:

- `認証`
- `対応`
- `大会前でも安心`

まで昇格させるのは危険。

高水準化するには、信頼要素を少なくとも次に分ける必要がある。

- `第三者認証 confirmed`
- `自社主張 confirmed`
- `ナビ/文言レベルの存在確認`
- `外部実績 confirmed`

### 6. validator 自体が誤判定している可能性がある

LP比較レポートの品質チェックには:

- `構造エラー: 競合比較サマリーが参考観測枠の後に来ている`

とあるが、本文順を見る限り主要構造は

1. エグゼクティブサマリー
2. 分析対象と比較前提
3. 競合比較サマリー
4. ブランド別評価

であり、少なくともこの指摘は怪しい。

つまり、今は

- レポート生成
- 品質判定

の両方に不安定さがある。

### 7. 広告運用の最終判断材料がまだ足りない

今回のレポートは前回より運用寄りになったが、まだ以下が不足。

- 媒体別KPI
- 指名 / 非指名 / リマーケの評価指標差
- CPA / CVR ではなく学習段階でまず何を見るか
- LP改善とキャンペーン改善の優先順位分岐

現状は「施策アイデア」は出るが、**運用会議でそのまま予算配分を決めるには浅い**。

## 実務目線の評価

### 使えるところ

- SAURUS は現状ブランドサイトで、非指名獲得LPとしては弱い
- WINZONE / HALEO は獲得型ECとしての勝ち筋が明確
- アミノバイタル / SAVAS は情報探索〜比較検討の受け皿として整理できている

この判断は前回よりかなり使える。

### まだ危ないところ

- 壊れた出力がそのまま返る
- 指名 / 非指名分類が混ざる
- 証拠の強さと広告コピーの強さが一致しない
- トークン超過で後半施策が欠ける

この4点が残る限り、**高水準の完成レポート**とは言えない。

## 改善方針

### 1. 品質チェックは `表示` ではなく `制御` に使う

品質チェックで以下を検知した場合:

- 日付矛盾
- 末尾欠け
- セクション欠損
- テーブル未閉塞

は、本文へ警告表示するのではなく:

- 自動短縮再生成
- Appendix除去再生成
- 失敗返却

のどれかに切り替える。

### 2. 日付・バージョン・対象数は renderer が唯一の owner になる

モデルに:

- `作成日`
- `分析実施日`
- `対象URL数`

を書かせない。

出すなら renderer が埋める。

### 3. レポートを二段構成にする

1回で本文 + Appendix + メタデータまで全部生成させるのではなく、

1. クライアント向け本文
2. Appendix / 実行メタ

を分離する。

必要なら Appendix は折りたたみ、または別タブに回す。

### 4. キーワード意図の taxonomy を固定化する

最低でも:

- `指名`
- `準指名`
- `非指名カテゴリ`
- `比較検討`
- `リマーケ対象`

を分ける。

ルール例:

- ブランド名含有あり → 指名 / 準指名
- 一般カテゴリ語のみ → 非指名
- `おすすめ / 比較 / 評判` → 比較検討

### 5. 信頼要素の階層を分ける

各訴求を次で扱い分ける。

- `第三者認証`
- `自社品質主張`
- `外部提携/実績`
- `コミュニティ/UGC`
- `単なるナビ or ラベル存在`

これを分けないと、
`ANTI DOPING` というラベルだけで `認証取得済み` のような誤昇格が起きる。

### 6. 施策レイヤーを媒体・KPIまで落とす

各施策について最低限:

- 媒体
- キャンペーン種別
- 主KPI
- 補助KPI
- 判定期間

を出す。

例:

- 指名検索: Impression Share / CTR / CPC / branded CVR
- 非指名検索: Search term fit / LP CVR / CPA / assisted conv
- Meta認知: LPV / CTR / engaged session / view content rate

### 7. 長文化しやすいブランド別評価を圧縮する

今の構成だと、4サイト以上でほぼ確実に後半が切れる。

対策:

- ブランド別評価を 2-3 bullet に圧縮
- 根拠列挙を Appendix に逃がす
- アクションを上位3件まで固定

## 新しいプラン

### Task A: Hard Fail 品質ゲート実装

内容:

- 日付矛盾
- truncation
- section欠落
- action table欠け

を検知したら、クライアント向け本文に警告を表示せず、再生成または失敗返却へ切り替える。

完了条件:

- `⚠ レポート品質チェック` がクライアント向け本文に出ない
- 品質基準未達レポートが配信されない

### Task B: メタデータ owner の一本化

内容:

- `実行日時`
- `作成日`
- `分析実施日`
- `対象URL数`

は renderer 固定値のみで表示する。

完了条件:

- 2026 と 2025 が同居しない

### Task C: 本文と Appendix の分離強化

内容:

- 本文は 5セクション程度に圧縮
- 抽出詳細 / 実行メタデータ / 品質監査は別枠

完了条件:

- 4サイト比較でも action plan が途中で切れない

### Task D: キーワード意図分類の修正

内容:

- `指名防衛` に非指名カテゴリ語を混ぜない
- `指名/非指名/比較検討` の語彙ルールを固定化

完了条件:

- `ランナー プロテイン` が `指名防衛` に入らない

### Task E: 信頼要素 taxonomy 強化

内容:

- `認証`
- `品質主張`
- `ブランド実績`
- `文言存在`

を別カラムで扱い、広告コピーへの転用許可も分ける。

完了条件:

- `ANTI DOPING` の単語確認だけで `認証取得済み` と書かれない

### Task F: 媒体別KPIレイヤー追加

内容:

各施策に:

- 媒体
- 配信目的
- 主KPI
- 補助KPI
- 評価タイミング

を追加する。

完了条件:

- 施策案がそのまま運用会議に持ち込める

### Task G: validator の deterministic 化

内容:

- 見出し順序
- テーブル閉塞
- 末尾欠け

をLLM判定ではなく deterministic に検査する。

完了条件:

- 生成物が正しいのに `構造エラー` と誤判定しない

## 受け入れ基準

1. 品質異常があるレポートは配信されない
2. 日付矛盾が消える
3. 4サイト比較でも action plan が最後まで出る
4. `指名防衛` と `非指名獲得` の分類が混ざらない
5. 信頼訴求の強さが証拠強度と一致する
6. 媒体・KPIまで落ちた施策提案になる
7. 品質チェッカーの誤警告がなくなる

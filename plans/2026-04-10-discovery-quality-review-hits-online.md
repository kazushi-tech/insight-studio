# Plan: Discovery Hub 出力品質レビュー — hits-online.jp

## Context

`hits-online.jp` の Discovery Hub 出力を広告運用プロフェッショナル視点でレビューした。
今回の出力は以下の3サイト比較:

- Hits Online Shop
- 蛇口堂 (jyaguchi-do)
- SANEI

結論として、**実務の叩き台としては有用**だが、**高水準の競合分析レポートとしてはまだ未完成**。
特に `データ制限時の断定`, `競合セット品質`, `広告運用への接続` に改善余地が大きい。

---

## 総評

### 良い点

1. **比較軸は実務に近い**
   - FV訴求力 / CTA設計 / 信頼構築 / ベネフィット訴求 / 価格心理学 / CV導線設計 は、広告LPレビューの主要論点として妥当。

2. **Hits の主問題抽出はかなり妥当**
   - 「正規代理店バッジは強い」
   - 「FVがGW休業告知で占有されている」
   - 「見積もりCTAはあるが購入導線が弱い」
   この3点は、広告運用上も重要な論点で、優先順位も大きくは外していない。

3. **SANEI の扱いは比較的まとも**
   - メーカー公式の安心感
   - ただし購入CVへの距離がある
   この整理は自然で、メーカーサイトと販売サイトの役割差もある程度踏めている。

4. **業界特化CRO分析の方向性は良い**
   - 水まわり・サニタリー業界で
     - 適合確認
     - 施工対応明示
     - 正規品保証
   を見るのは、一般的なECレビューより一段実務寄り。

### 弱い点

1. **データ制限下の断定が強すぎる**
   - 蛇口堂に対する
     - 「信頼性ゼロ」
     - 「離脱確実」
     - 「広告出稿停止を含む緊急対応が必要」
   は、スクショ上の根拠だけでは断定過剰。
   - ここは「評価不能」と「低評価」を分離すべき。

2. **競合セットの質がまだ不安定**
   - Hits と SANEI は比較価値がある。
   - ただし 蛇口堂 は文字化けでまともに読めていない時点で、比較対象として残すべきではない。
   - `低品質取得サイトを自動除外して別候補に差し替える` 仕組みが必要。

3. **広告運用アクションへの接続が弱い**
   - 現状は CRO 診断としては読めるが、
     - 検索広告で何を止めるか
     - どの訴求軸で広告文を差し替えるか
     - LP AB テストを何本走らせるか
   まで落ちていない。

4. **類推の品質にムラがある**
   - Hits のターゲット/ポジション仮説は比較的妥当。
   - 一方で `[本文推定]` が付く箇所の中には、証拠との結び付きが弱いものがある。
   - `本文推定` と `強推定` が同列に見えるのが問題。

5. **ベンチマークの階層が粗い**
   - `ECサイト`
   - `コーポレートサイト`
   だけでは足りない。
   - 今回は少なくとも:
     - 正規代理店EC
     - メーカー公式ブランドサイト
     - ニッチEC / 取得不良サイト
   を分けて評価したい。

---

## 判定

### 考察の精度

**中の上。**

- Hits: 良い
- SANEI: まずまず
- 蛇口堂: 低い

### 分析の質

**実務初稿レベル。**

- 論点の置き方は悪くない
- ただし「証拠の強さ」と「断定の強さ」が一致していない

### 類推の水準

**まだ高水準には達していない。**

- 高水準と言うには
  - 不確実性管理
  - 競合選定の精度
  - 広告運用施策への直結性
  が不足している

---

## 改善方針

### 1. データ制限時の扱いを厳格化

`取得失敗 / 文字化け / 主要項目欠落` のサイトは:

- スコアを無理に付けない
- `評価保留`
- `比較対象から除外候補`

として扱う。

### 2. 競合候補の自動差し替え

以下の条件を満たした候補は自動除外:

- 本文抽出量が閾値未満
- 主要フィールドが一定数以上欠損
- 文字化け率が高い
- fetch 成功でも比較根拠が薄い

そのうえで次点候補へ差し替える。

### 3. 不確実性ラベルを3段階化

各所見に:

- `高信頼`
- `推定`
- `評価不能`

を付ける。

`推定` と `評価不能` を今より明確に分離する。

### 4. 業界特化分析を広告運用へ接続

水まわり・サニタリー業界向けに、出力へ以下を追加:

- 価格訴求の型
  - 正規品保証
  - 施工安心
  - 適合確認
  - 納期 / 在庫
- 検索意図の型
  - 指名
  - 比較検討
  - 施工前相談
  - 品番 / 適合確認
- 即時アクション
  - 広告文
  - LP改善
  - 除外キーワード
  - 予算配分

### 5. サマリーを「広告判断」中心へ再設計

`比較結論` を単なる要約ではなく、以下の形に変える:

- 今勝てる訴求
- 今弱い訴求
- 直近7日でやるべき施策

## 実装タスク

### Task A: 競合候補品質ゲート

対象:

- `web/app/services/discovery/discovery_pipeline.py`
- `web/app/services/discovery/candidate_ranker.py`

内容:

- 文字化け検知
- 抽出品質スコア
- 低品質候補の自動差し替え

### Task B: 出力スキーマの信頼度追加

対象:

- `web/app/analyzer.py`

内容:

- 各仮説・各比較所見に `confidence` 相当の文言ルール追加
- `評価不能` の扱いを明示

### Task C: 業界特化広告アクションの追加

対象:

- `web/app/analyzer.py`

内容:

- `広告運用アクション` セクション新設
- 各ブランドごとに
  - 勝ち訴求
  - 負け訴求
  - 直近改善案
  を出す

### Task D: 比較結論の断定抑制

対象:

- `web/app/analyzer.py`

内容:

- データ不足サイトへの強断定を禁止
- `広告停止` のような重い提言は、高信頼条件を満たす場合のみ許可

---

## 受け入れ基準

1. 文字化けサイトが比較表の主役にならない
2. `評価不能` と `低評価` が明確に分離される
3. Hits のようなサイトで、広告運用アクションが3件以上具体化される
4. サマリーを読んだだけで
   - 何を訴求するか
   - 何を修正するか
   - 何を比較検証するか
   が分かる

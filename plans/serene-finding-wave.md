# Discovery Hub 分析品質向上 — プロンプト改修プラン

## Context

Discovery Hub がようやく1分台で安定動作するようになった。しかし出力される分析レポートの品質を広告運用プロフェッショナルの視点でレビューすると、以下の重大な問題がある。

### 現状の問題点

#### 1. 「取得不可」を"サイトの弱み"と誤認（致命的）
スクリーンショットでSAURUSの弱みに「CTA・価格・顧客の声がすべて取得不可→コンバージョン設計が弱い可能性」と記載。
これは**HTML抽出の技術的制限**であり、実際のサイトにはCTAも価格も存在する。
この誤認により分析の信頼性が根本的に損なわれている。

#### 2. LP効果のスコアリングがない
単一URL分析プロンプト(`build_competitive_lp_prompt`)には `| 評価項目 | スコア(1-5) | コメント |` があるが、
Discovery用の比較プロンプト(`build_deep_comparison_prompt`)にはLP評価スコアが存在しない。
広告運用者はスコアで即座に優劣を判断したい。

#### 3. max_output_tokens=2048 で後半ステップが切り捨て
3サイト × Step1〜5 + テーブル = 3000トークン以上必要。
2048トークンだとStep4（ギャップ分析）・Step5（改善提案）が切り捨てられる可能性が高い。
**最も価値あるアクション提案が欠落するリスク。**

#### 4. コンバージョン設計分析の欠如
ファーストビュー効果、CTA配置・文言評価、フォーム到達性、CV導線分析がない。
広告LPの評価でこれがないのは致命的。

#### 5. 提案が抽象的
「差別化アクション3つ」では粒度が粗い。
広告運用者は「具体的なヘッドラインコピー案」「CTAボタン文言の代替案」「A/Bテスト仮説」が欲しい。

#### 6. テーブルにURLを使い読みにくい
比較テーブルのカラムヘッダーがフルURL（`saurusjapan.com | ajinomoto.co.jp/aminovital | upathlete.jp`）で幅が広すぎる。
ブランド名で十分。

#### 7. 総合サマリーにLP品質指標がない
現在: `サイト | ブランド | ポジション仮説 | 一言要約`
欲しい: `ブランド名 | LP評価(A-D) | ポジション | 一言要約 | 最優先改善`

### 良い点（維持すべき）
- 競合特定精度は高い（SAURUS vs amino VITAL vs UP ATHLETE は妥当な競合三角形）
- ポジショニング分化が明確（ニッチランナー vs マス権威 vs コスパ多競技）
- 具体的データ引用あり（BCAA 3000mg等）
- 【推定】ラベルの活用
- 比較結論の洞察は鋭い

    # ブランド名推定: H1 > title > URL

        brand_name = data.h1
    elif data.title:
        brand_name = data.title.split('|')[0].split('-')[0].split('–')[0].strip()[:30]

    header = f"### {brand_name}（{data.url}）" if brand_name else f"### {data.url}"

## 検証手順

1. `python -m py_compile web/app/analyzer.py` でコンパイル確認
2. 既存テスト実行: `pytest tests/test_analyzer.py -v`（テストがあれば）
3. git commit & push → Render 自動デプロイ
4. デプロイ後、Discovery Hub で `saurusjapan.com` を再分析
5. 以下を確認:
   - 総合サマリーに LP評価(A-D) + 最優先改善 が含まれるか
   - 「取得不可」が弱みとして挙げられていないか
   - LP効果スコア(1-5)テーブルが各サイトに出力されるか
   - コンバージョン設計分析セクションが存在するか
   - アクション提案に具体的コピー例があるか
   - 比較テーブルのヘッダーがブランド名になっているか
   - 分析が途中で切れていないか（3072トークンで全ステップ完了）
6. 所要時間が90秒以内に収まっていることを確認

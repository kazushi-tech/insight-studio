# Discovery Hub レポート＆UI/UX 評価 + Stitch 2.0 改善プロンプト

## Context

ユーザー（広告運用責任者）から、以下3点の依頼があった：

1. **Discovery Hub レポート本体（水栓金具・サニタリー用品EC 競合分析）の分析品質評価** — 広告運用プロの視点で
2. **競合発見画面の UI/UX 評価** — Webデザインプロの視点で、スクリーンショット8枚添付
3. **改善点を Stitch 2.0 に渡すためのプロンプト作成** — 詳細版

前提：`src/pages/Discovery.jsx` と `src/components/report/v2/` には既に Stitch 2.0 Phase 1-5A 相当（envelope 優先 / MD フォールバック / v2 tokens.css / MD3 準拠）が実装済み。本プランは「実装済みv2をさらに次段階（v3相当）に引き上げるための追加改善」を提案するもの。コード変更は行わず、このplanファイルそのものが成果物となる。

## Part 1 — レポート内容の品質評価（広告運用プロ視点）

### 総合評価：★★★☆☆（コンサル初級～中級相当、実務即応性に難あり）

#### ✅ 優れている点

| # | 評価 | 所見 |
|---|------|------|
| 1 | **ファクト／推定の分離設計** | 【確認済み】【推定】【市場推定】のバッジ運用で、誇大解釈を防ぐ良質なガバナンス |
| 2 | **3層勝ち筋の構造化** | 正規代理店型 / メーカー直営型 / 専門店型の二分＋実績訴求の言語化は、セグメント戦略の土台として使える |
| 3 | **購買行動フローの仮説化** | Pinterest/IG → Google検索 → 見積り依頼 の経路推定は、媒体ポートフォリオ設計の出発点として適切 |
| 4 | **信頼シグナル階層の認識** | L1（第三者認証＝GROHE/Hansgrohe正規認定）の概念が明示されており、信頼性アセットの評価観点を持っている |

#### ❌ 実務上の致命的な弱点

##### 【CRITICAL-1】市場規模の桁違い誤り
> 「日本市場規模 200,000〜250,000 億円」 = **20〜25兆円**

- BtoC EC 全体でも約19兆円（2024年経産省）
- 水栓・サニタリー用品ECのみで20兆円超は**物理的にあり得ない**
- カテゴリ特化なら数百億〜数千億円規模が現実値
- **原因**: プロンプト側で「市場規模」と「BtoC EC 全体規模」を混同している可能性。shared_specs または promptテンプレの数値レンジ制約不備
- **対策**: `backends/market-lens-ai/web/app/confidence_tier_validator.py` に数値サニティチェック（カテゴリEC市場 < 1兆円上限など）を追加

##### 【CRITICAL-2】広告投資推定レンジが意思決定に使えない
> 「Hits Online / SANEI: 300〜5,000万円」「パパサラダ: 200〜3,000万円」

- 幅が**16.7倍**（300→5,000）、広告プランニングの参考値にならない
- 広告主が知りたいのは「このカテゴリで月300万と500万でどう変わるか」の**粒度**
- 「low 信頼度」と自白してはいるが、それなら**レンジを提示しない or 「不明」表記**が誠実
- **対策**: shared_specs で信頼度 low 時はレンジ表示をスキップ／代わりに「推定根拠不足」と明示

##### 【CRITICAL-3】アクショナブルさの欠如
> 「Hits Online の見積り導線を検索広告の着地先として強化」

- **Why(なぜ)**: 正規代理店認定が第三者証明になる → ○
- **What(何を)**: 見積り導線強化 → ○
- **How(どう)**: 媒体選定・入札戦略・LP改善項目・予算配分 → **✗ 完全欠落**

実務者が次にやることが決まらない。以下の粒度まで踏み込むべき：
- 媒体: Google Search P-MAX or Demand Gen か
- キーワード: 「GROHE 水栓 代理店」「法人 見積り」等の具体例
- LP改善: Above the fold に見積り依頼 CTA、信頼バッジの配置高さ
- 予算配分: 指名防衛 : 非指名獲得 = X : Y 推奨

##### 【WARNING-1】類推の論拠が薄い箇所
- 「ブランド指名検索は限定的」→ 検索ボリュームの根拠データ無し
- 「施工会社・デザイン会社（法人）がメインターゲット」→ 本文の「プロ向け商材」一文のみが根拠。規模感（法人比率）の推定なし
- 「検討期間3〜6ヶ月」→ 一般論であり、水栓カテゴリ固有のデータではない

##### 【WARNING-2】競合セットの網羅性不足
- 「今回未分析: grohe.co.jp / kanzaipro.com / kvkaqua.co.jp / miratap.co.jp」
- **真の競合（GROHE Japan, ミラタップ）が未分析**のまま結論を出している
- degrade-retry で 4/6 サイトが落ちている時点で **レポートを出すべきか判断すべき**
- **対策**: 実競合分析対象数 < 3 or degrade-retry率 > 50% で「再実行推奨」バナーを表示

#### 📊 類推レベル総評
- **コンサルの「現状整理フェーズ」としては合格**（Situation分析 ★★★★☆）
- **「戦略提言フェーズ」としては不合格**（How-to の解像度 ★★☆☆☆）
- AI分析として期待される「**人間より速く・広く・整合的に**」のうち、「**整合的**」に数値誤りで疑義が出ている点が最大の改善ポイント

## Part 2 — 競合発見 UI/UX 現状評価（Webデザインプロ視点）

### 総合評価：★★★☆☆（情報構造は硬い、表現力に伸びしろ）

#### ✅ 優れている点

| # | 評価 | 所見 |
|---|------|------|
| 1 | **Botanical Green × warm off-white の配色** | 分析SaaSとして硬すぎず・柔らかすぎず、業界識別性が高い |
| 2 | **左サイドナビの情報階層** | 競合LP分析 / 広告分析 / 設定の3グループ化は迷子を防ぐ |
| 3 | **COMPETITOR MATRIX × BRAND RADAR の2ペイン並列** | ヒートマップ × レーダーは「俯瞰→深掘り」の視線動線に合致 |
| 4 | **品質チェック警告パネル** | 欠損セクションを明示するのは誠実で、ユーザー信頼を育てる |
| 5 | **v2 バッジ表示** | 新UIへの移行意識を見せる運用がよい |

#### ❌ 視覚／情報設計の課題

##### 【UI-1】メタ情報ストリップが視覚ノイズ
```
● 完了  search: 53ab1c09b5b3  水栓金具・サニタリー用品のオンラインショップ  7件候補  3サイト分析  Claude  2分26秒
```
- 「完了」ステータスと「search ID」と「カテゴリ」と「件数」と「エンジン」と「処理時間」が**同じ視覚階層**で横並び
- ユーザーが最初に見るべき「カテゴリ/件数」が埋没
- **改善**: カテゴリをH1サイズ、件数を chip、search ID は `details` で折り畳み、処理時間は小さな時計アイコン＋数字のみ

##### 【UI-2】COMPETITOR MATRIX が省略されすぎて価値を失っている
スクリーンショット1で Hits Online の1行しか見えない。スクロールで SANEI/パパサラダが現れると思われるが：
- **「比較」が第一目的なのに、同時視認できていない** → 比較UIとして失格
- 3ブランド横並びであれば、1画面に収まる設計が必須
- **改善**: マトリクスは縦=評価軸、横=ブランド（転置）。6軸×3ブランド = 18セルなら1画面に収まる

##### 【UI-3】BRAND RADAR チャートの3D風表現が誤解を生む
- 現状は等角投影（アイソメトリック）風のレーダー
- **レーダーチャートは平面投影が標準**。立体感は「深さ」の錯覚を生み、値の比較精度を下げる
- しかも Hits Online 単体表示で、比較の意味が薄い
- **改善**: 標準の平面レーダー＋3ブランド重ね描き（半透明fill）。1ブランドフォーカス時はオパシティ変更

##### 【UI-4】レポート本文の「マークダウン丸出し感」
スクリーンショット2-8で露呈：
- 見出し階層（##, ###）がそのまま反映されており、情報密度調整が足りない
- **「最優先施策」が箇条書きの中に埋没**。視線誘導のフックが無い
- テーブルが素のHTMLテーブル風でカード感がない
- 「3-1. 市場概況」「3-2. 競合広告投資推定」などのナンバリングが冗長で、スキャン妨害

**改善方向**: Notion/Coda風のブロック型レイアウトへ。各セクションを「カード」または「アコーディオン」化し、**最優先施策のみ常時展開**、他は折り畳み初期状態

##### 【UI-5】信頼度表示の視覚強度不足
- 「low」「low」「low」「低」と並んでいるが全て同じ太字テキスト
- **どれくらい low なのか、感覚的に伝わらない**
- **改善**: ConfidencePill をドット3つ（● ○ ○ = low, ● ● ○ = medium, ● ● ● = high）＋ カラーコード

##### 【UI-6】データカバレッジの視覚弱さ
- 赤い帯（Main CTA 未取得, Pricing 未取得）は良い兆候
- しかしサイト名が単独行で、どのサイトのどのフィールドが何%取れているか**パーセンテージが不明**
- 「1/12 取得成功」という分母・分子表記は技術者向け
- **改善**: 横棒グラフ（12分割）＋ 取得率 % 表示。フィールド名をアイコン化（💰 pricing, 🎯 CTA 等）

##### 【UI-7】TRACKING KPI 目標値が空ボックス
スクリーンショット8で4つのボックスがあるが、「入力ブランド CONTROL / 実競合比較対象 / 実競合比較対象 / 項目 推定値」と**ラベルのみで中身空**
- 何を入力すべきか、どう使うかが不明
- 初見ユーザーは確実に「壊れている？」と誤解する
- **改善**: 空状態メッセージ＋プレースホルダ値＋「KPI設定ガイド」リンク。もしくは **デフォルトでは非表示**、ユーザーが「KPIを設定」ボタンを押したら展開

##### 【UI-8】発見されたLP一覧のサムネイルがバラバラ
- SANEI は白背景ロゴ、パパサラダは緑円形、管材プロは赤文字 → OGP/favicon由来で統一感なし
- **改善**: スクリーンショット自動撮影 → 共通アスペクト比（16:10）で統一サムネイル生成

##### 【UI-9】文字サイズ S/M/L とダークモードの動線分断
- ヘッダー右上にダークモード/設定、レポート内側に S/M/L
- **両方とも「表示設定」なのに分離**
- **改善**: レポート右上に View Settings ポップオーバーで一元化

##### 【UI-10】品質チェック警告と「エグゼクティブサマリー」カードの視覚衝突
- 黄色警告パネル（セクション欠損）と、レポート本文のカードが近接
- **「欠損あり」を見せつつ、本文は読ませる**意図が見えない → 欠損を直す動線（「再実行」「補完リクエスト」）が無い
- **改善**: 警告パネルに「このセクションを再生成」CTA を追加

### UX 全体総評
- **Analytical densityは十分**、日本的SaaS平均より情報量が多い
- **しかしVisual priority（視線優先順位）設計が弱い**、1枚で「何を見るべきか」が決まらない
- **Stitch 2.0 v2 は技術的土台としては優秀**、後はデザインディレクション次第で世界水準に届く

## Part 3 — Stitch 2.0 改善プロンプト（コピペ用）

以下を Stitch 2.0 にそのまま投入する想定のプロンプト。コンポーネントとしては既存の `src/components/report/v2/*` を発展させる方針を前提とする。

### 🎨 Stitch 2.0 プロンプト本文

````
# Insight Studio Discovery Hub — Report View V3 Redesign

## プロダクトコンテキスト
- サービス: Insight Studio（広告運用・競合分析SaaS、PC専用）
- 対象画面: /discovery（競合発見画面）
- 現状: React + Tailwind CSS v4 + CSS Modules (MD3 tokens) で v2 実装済み
- ユーザー: 広告代理店プランナー / 事業会社 CMO / EC 運用担当者
- 利用シーン: 朝会で競合状況を5分で把握、詳細は深掘りセクションで確認

## デザインシステム（継承）
- Primary: Botanical Green #003925
- Surface: Warm off-white #fafaf5
- Container Lowest: #eeeee9
- Gold accent: #d4a843
- Font: Manrope (display) + Inter (body), both Japanese subset
- Card radius: 16px / Button radius: 12px
- Motion: cubic-bezier(0.2, 0, 0, 1), durations 150/200/400ms
- Elevation: shadow-sm, shadow-md（MD3 Elevation 1/2）

## 改善の核心（5 hero principles）
1. **「1画面1勝ち筋」** — ユーザーが最初に見るべき情報を絶対的に1つに絞る
2. **「比較は横並び、深掘りは縦送り」** — Matrix/Radar は横、詳細は縦
3. **「信頼度はドットで直感化」** — 文字より視覚量で伝える
4. **「情報密度のレイヤー設計」** — Overview / Insight / Detail の3層、それぞれが自立
5. **「欠損は動線化する」** — 警告だけでなく「再生成」アクションに接続

## 画面構造（Figma / HTML プロトタイプ想定）

### ヘッダー（固定、60px）
- 左: Insight Studio ロゴ + ブレッドクラム（📁 カメラの大林 > 競合発見）
- 中央: 空 or 検索バー
- 右: テーマ切替アイコン / ユーザーアバター（既存踏襲）

### ヒーロー入力エリア（カード、padding 32px）
- h1: 「競合発見 — Competitor Discovery」 Manrope 28px/700
- subtitle: Claude Sonnet 4.6 による自動分析（クリックで engine 詳細 tooltip）
- URL 入力: 幅 80%、右に「競合を発見」プライマリボタン
- ステータスチップ: 「● 完了」が横にサブトル表示

### メタ情報ストリップ（水平、薄いカード）
- 左: カテゴリ名（大）＋ 件数 chip
- 中央: 分析時刻・処理時間（時計アイコン + 数字）
- 右: 「Claude」エンジンバッジ、「search: xxx」details（折り畳み）
- 最下段: 「再分析」「共有」「PDF」「v1/v2 Toggle」を icon button 群で整列

### ★セクション 1: Executive Briefing（最優先施策ヒーロー）
**目的: 画面を開いて3秒で「次の一手」が決まる**
- 背景: ゴールドグラデーション薄め（#d4a843 → transparent）
- タイトル: 「🎯 今週の最優先施策」Manrope 24px/700
- 3つの KPI カード横並び:
  - カード1: 「指名防衛強化」Hits Online 見積り導線、効果予測、推奨予算
  - カード2: 「セット商品拡大」パパサラダ、キーワード例、想定CPA
  - カード3: 「内部リンク整備」SANEI、工数、優先度
- 各カード右下: 「詳細を見る」→ 該当セクションへスクロール

### ★セクション 2: Competitor Matrix（転置版）
**目的: 3ブランド × 6評価軸を1画面で把握**
- 構造: 列=ブランド、行=評価軸（転置済み）
- 各セル:
  - 上段: verdict symbol（▲強 / ＝同等 / ▼弱）+ 色ドット
  - 下段: 根拠要約（1行、最大30文字）
  - hover/click: モーダルで full evidence 表示
- 最左列: 評価軸名 + ℹ️ tooltip（定義）
- 最上段: ブランド名 + サイト種別バッジ（正規代理店EC / メーカー直営 / 専門店EC）
- 信頼度: 各ブランド列の下に ● ● ○ ○ ドット

### ★セクション 3: Brand Radar（平面 × 重ね描き）
**目的: 競合間の強弱バランスを直観的に比較**
- 標準レーダーチャート、6軸（検索意図一致 / FV訴求 / CTA明確性 / 信頼構築 / 価格・オファー / 購買導線）
- 3ブランドを半透明塗りつぶしで重ね描き
  - Hits Online: Botanical Green #003925, fill-opacity 0.3
  - SANEI: Accent Blue #4a7c8c, fill-opacity 0.2
  - パパサラダ: Gold #d4a843, fill-opacity 0.2
- 凡例: ピル型トグル、クリックで該当ブランドを前面化
- 右側: Axis summary table（どの軸で誰が勝っているか、1行要約）

### セクション 4: 市場スナップショット
**目的: 定量情報を視覚化、桁違い誤りを防ぐ**
- 4列グリッド、各カード:
  - 市場規模: **数値 + ユニット + 信頼度ドット + ソースURL**
  - 成長率: スパークライン（過去3年推定）
  - 検索ボリューム: 月次チャート（季節性明示）
  - 平均 CPC/CVR: ゲージ（カテゴリ平均対比）
- 重要: 信頼度 low の場合は **具体値を隠し「推定根拠不足」と明示**

### セクション 5: 競合広告投資推定
**目的: レンジを使える形で可視化**
- 横棒グラフ、3ブランド
- 各棒の右端に「低信頼」ドット + Tooltip で推定根拠
- **レンジ幅が10倍超の場合は赤枠警告「この推定は意思決定に使わないでください」**

### セクション 6: 消費者インサイト（購買フロー）
**目的: 購買行動を直感的に**
- ステップフロー図（横スクロール、3-5ステップ）:
  1. 🔍 認知: Pinterest / Instagram（デザイン参考）
  2. 📊 比較: Google検索（商品・価格確認）
  3. 📞 決定: 見積り依頼 / セット購入
- 各ステップ下にブランド別の関与度バー
- 下部: ターゲット層カード（3枚、ブランド別）

### セクション 7: ブランド別詳細評価（アコーディオン）
**目的: 1ブランド1カード、畳める**
- カード3枚縦積み、デフォルト1枚目展開
- 各カード:
  - ヘッダー: ブランドロゴ + 名前 + サイト種別 + データ品質スコア
  - 本体: 要約 / 強み / 弱み の3列グリッド
  - 下部: 評価軸テーブル（6行）、判定ピル + 根拠要約 + 証拠強度バッジ

### セクション 8: データカバレッジ（視覚強化版）
**目的: 欠損を動線化**
- 各サイトを行、各フィールドを列のヒートマップ
- 列: title / description / hero_copy / pricing / main_cta / features / testimonials / faq / brand_mentions / L1_signals / OG_image / sitemap
- セル色: 緑（取得成功）/ 黄（部分取得）/ 赤（未取得）
- 右端: 取得率バー + 「再取得」ボタン

### セクション 9: 追加候補（次回分析候補）
- 「今回未分析の発見候補」カード
- 各候補に「分析する」CTA → クリックでキューに追加
- 除外理由バッジ（品質ゲート除外 / degrade-retry / 未実行）
````

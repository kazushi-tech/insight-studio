# AI考察エンジン 品質改善 — 分析深度・類推精度・フォーマット多様性

## Context

AI考察ページ(`AiExplorer.jsx`)の出力を広告運用プロの観点でレビューした結果、以下の課題を特定:
1. **類推が弱い** — 根拠データの交差参照なしに「〜の可能性がある」と列挙するだけ
2. **アクションが具体性不足** — 「見直しを推奨」で止まり、予算・期限・期待効果がない
3. **異常値の分析が浅い** — 直帰率100%を「調査推奨」で終わらせている
4. **フォーマットが箇条書き過多** — 散文・テーブル・箇条書きの使い分けができていない
5. **モバイルファースト・時間帯戦略・クロスチャネル分析が欠落**

    .filter(t => typeDirectives[t])

  const comparisonDirective = periods.length > 1

        `- 全指標の前後比較を表形式で提示`,
        `- 改善指標と悪化指標を明確に分離`,

  return [

    `データ種別: ${types || 'GA4ウェブ解析データ'}。${periodInfo}`,
    ``,

## 変更3: `system_bq.txt` 拡張

**ファイル:** [system_bq.txt](tmp_ads_insights_repo/web/app/prompts/system_bq.txt)

### 3a: 異常値分解プロトコル追加（L39の後に挿入）

```
━━━ 異常値・外れ値の分析プロトコル ━━━

直帰率100%、CV率0%等の極端な値が見られた場合:

1. 計測artifact確認（最優先）
   - 他LPの直帰率と極端に乖離していないか確認
   - GA4タグ実装問題（二重タグ・欠落）の可能性を指摘

2. 流入元別分解
   - source/medium別に分解し特定チャネルへの偏りを確認

3. デバイス別分解
   - モバイル/PCで該当指標に差があるか確認

4. 改善提案の深度
   - 「調査を推奨」で止めない。A/Bテスト設計（テスト対象・期待効果・測定期間）を含める
```

### 3b: ベンチマーク参照セクション追加

```
━━━ GA4指標ベンチマーク（類推時の比較参考値）━━━

| 指標 | 一般的水準 | 注意閾値 |
| --- | --- | --- |
| 直帰率 | 40-60% | 70%超で改善優先 |
| PV/セッション | 1.5-3.0 | 1.3以下は回遊性課題 |
| CVR（EC） | 1-3% | 1%未満はファネル課題 |
| CVR（リード） | 2-5% | 2%未満は改善余地大 |
| カート→購入率 | 50-70% | 40%未満は決済課題 |
| 新規ユーザー比率 | 30-40% | 20%以下は集客力低下 |
| モバイル比率（B2C） | 60-80% | 80%超はモバイルファースト必須 |

使用時は【類推】として扱い、業種・規模により異なる旨を併記。
```

### 3c: 類推ルール強化（L15-23を差し替え）

現在:
```
━━━ 類推観点（変動原因の仮説立案時に参照）━━━
外的要因から変動原因を推測する際は、以下の観点を参考にすること：
- 曜日要因: ...
- 月初月末: ...
（以下略）
```

差し替え:
```
━━━ 類推観点（厳守ルール）━━━

**基本ルール**: 類推は許可するが、必ず根拠となるデータポイントを併記すること。
「〜の可能性がある」だけで終わらせない。以下の証拠種別から最低1つを添える:

- 日付相関: 特定日の変動とイベント日の照合
- 地域相関: 地域別データでの当該地域増加検証
- 流入元相関: 当該チャネルの変化データ
- デバイス相関: デバイス別パターンによるユーザー層推定

外的要因仮説の観点:
- 曜日要因 / 月初月末 / 祝日・季節性 / 天候 / 外部露出 / 競合動向 / 内部施策
```

### 3d: Markdown品質方針の強制力強化（L41-124の強化）

既存の品質方針は良い内容だが、AIが無視している。冒頭に強制力を追加:

```
━━━ Markdown品質方針（最高優先・厳守）━━━

**⚠️ これに違反した出力は品質不合格として却下される。**

**構成比率の目安**: 段落（散文）≥ 50% / テーブル ≥ 20% / 箇条書き ≤ 30%

**禁止事項**:
- ❌ セクション全体を箇条書きのみで構成すること
- ❌ 「〜が増加しました」等の事実羅列（見れば分かることは書かない）
- ❌ 比較すべき数値を箇条書きで羅列（テーブルを使うべき場面）

**フォーマット使い分け**:
（既存の📊表 / 📝段落 / 📋箇条書き / 💬引用ブロック の説明を維持）
```

## 検証方法

1. `npm run dev` で開発サーバー起動
2. `/ads/ai` ページで分析を実行
3. 以下を確認:
   - [ ] AI応答に散文（段落）が50%以上含まれている
   - [ ] 数値比較にテーブルが使われている
   - [ ] 類推に「日付相関」「地域相関」等の根拠タグが付いている
   - [ ] アクションに P0/P1/P2 + 具体性 + 期待効果が含まれている
   - [ ] 直帰率100%のLPで計測artifact確認が最初に言及されている
   - [ ] モバイル比率70%超のデータでモバイルファースト観点が最優先されている
   - [ ] Quick Analysis（サジェストchip）が正常動作する

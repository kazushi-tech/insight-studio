# 旧認証・互換列の削除ゲート（Migration 013）

## 結論

`013_legacy_cleanup` は現時点では作成・実行しない。これは未実装ではなく、顧客招待完了後の30日間の移行観測を終えるまで、旧資格情報と互換列を安全に残すための意図的な停止である。

## 観測開始条件

次をすべて満たした日時を、監査イベントとリリース記録へ `legacy_observation_started_at` として残す。

- 対象利用者へのClerk招待が完了している
- workspace / project権限への移行件数が旧案件台帳と一致している
- 旧ログインから新ログインへ戻す必要がある未解決障害が0件である
- 旧JWT secretをローテーション済みである
- 共有管理者パスワードを無効化済みである

## 30日間の観測条件

- 旧ログインAPIへの成功アクセスが0件
- legacy `case_id` だけを使う顧客アクセスが0件
- v1アダプターでしか表示できない新規レポートが0件
- workspace / project不一致、招待失敗、権限復元依頼を日次確認する
- 集計ログにはメール、dataset、JWT、IP、秘密値を残さない

1件でも依存が観測された場合は、その最終観測時点から30日を数え直す。

## Migration 013作成条件

30日間の条件達成後、次の順で作業する。

1. managed PostgreSQLの復元可能なバックアップとPITR状態を確認する
2. 削除対象列・テーブル・環境変数・APIの利用が0件である証跡を保存する
3. 参照削除を先行したアプリをpreviewで検証する
4. destructive migrationを別PRで作成し、DB担当とセキュリティ担当の承認を得る
5. release jobだけからdirect connectionで実行する
6. 24時間のエラー監視後にゲートを完了扱いとする

## 禁止事項

- 観測開始日時がない状態で30日経過とみなさない
- 起動時migrationや`create_all`で削除しない
- file repositoryや`/tmp`を退避先にしない
- migration downgradeを本番ロールバック手段にしない
- とどくくん、YouTube広告、Google Ads API向けの互換列や仮テーブルを追加しない
